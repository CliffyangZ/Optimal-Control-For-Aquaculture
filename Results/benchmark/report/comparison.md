## 4. 重點觀察

- **整體 AP（不受門檻影響）**：RF-DETR 最高（R-m 0.357、R-s 0.354），其次 YOLO26（Y-m 0.288），D-FINE 最低且 m 反而比 n 差（D-m 0.081）。
- **Feed（核心 KPI）**：以 conf 0.25 的 F1 看，YOLO26 最佳（Y-m 0.66、Y-s 0.64），RF-DETR 次之（R-m 0.56），Feed recall 全部未達 `feed_recall_min` 0.75。AP50-95 則 YOLO（0.17–0.19）略高於 RF-DETR（0.15–0.16），兩者 CI 有重疊。
- **Fish**：RF-DETR recall 高（0.70+），YOLO precision 較高；AP50-95 以 R-m 0.369 最佳。
- **尺寸趨勢**：Y、R 皆 n→s 提升明顯、s→m 增幅小（R：0.354→0.357；Y：0.254→0.288），s 可能是性價比點。
- **D-FINE 異常**：recall 近 0（多數分數 < 0.25），固定門檻下 P/R/F1 無意義。D-s 的評估器 val AP（0.1993）與訓練器自己算的相同，故非評估錯誤；較可能是訓練不足／自訂 HF 訓練迴圈的設定問題（D-m 比 D-n 差也支持這點）。建議先檢查 D-FINE 訓練（學習率、epoch、分數校準）再下結論，不要逐模型調門檻（FR-004）。

## 5. 限制

- 單次 seed 42；held-out 影像數有限，CI 寬（尤其 feed recall），n/s/m 小差距不顯著。
- RF-DETR 使用官方解析度（384/512/576），YOLO/D-FINE 為 640，不是同一輸入大小。
- 尚未有：latency/VRAM（profile）、feed 數量一致性（Bland–Altman）、合成資料集、決策規則，故尚不能選出 edge / server 模型。
- 完整數值：`Results/benchmark/report/evaluation_table.csv`；各 run：`Results/benchmark/runs/<run>/metrics.json`。
